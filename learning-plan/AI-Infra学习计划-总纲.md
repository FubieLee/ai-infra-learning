## 〇、两三年后 AI Infra 还是主轴吗？——前瞻判断

**结论：是，而且重心会更偏向"推理侧 Infra"。** 依据（2025–2026 公开数据）：

| 信号 | 数据 | 含义 |
|---|---|---|
| 推理算力超训练 | Deloitte：2026 年推理已占 AI 算力约 2/3；Gartner：2028 年推理:训练 ≈ 3:1，中国或达 4:1 | 行业重心从"训练大模型"转向"大规模跑模型" |
| 推理市场增速 | 全球推理市场 2025 年 $1135 亿 → 2030 年 $2538 亿，翻倍以上 | 推理 Infra 人才需求持续扩大 |
| Agent 爆发 | 火山引擎日均 Token 调用 16.4 万亿（1 年增 137 倍）；智能体进入规模应用期 | 推理负载呈指数增长，服务化/调度/成本优化人才紧缺 |
| 芯片格局分化 | Gartner：2027 年 AI 加速器出货将超 GPU；专用推理芯片（ASIC/NPU）崛起 | 需要懂多种硬件的软件人才，跨平台优化能力升值 |
| 人才结构 | 推理时代要求实时监控、延迟管理、边缘部署技能；高性能计算工程师供需比 0.15（7 岗争 1 人） | 供需缺口在 Infra 侧，不在算法侧 |

**三个注意点（决定你怎么学）：**
1. **主轴内部重心偏移**：训练 Infra（大集群预训练）需求增速放缓，推理 Infra（服务化、量化、调度、端侧）是增量主战场。学习时训练侧"理解原理即可"，推理侧要"源码级精通"。
2. **硬件多元化**：不再是纯 NVIDIA/CUDA 世界，国产卡（昇腾/寒武纪）、专用推理芯片需要适配人才。CUDA 是基本功，但要有跨平台意识。
3. **能效与成本成为核心指标**：电力限制下，"每 Token 成本"是推理 Infra 的北极星指标，量化/压缩/调度优化价值凸显。

**风险对冲策略**：以推理 Infra 为主轴（D7），保留训练 Infra（D6）理解、模型压缩（D8）互锁、AI 编译器（D10-2）作第二曲线——这套组合在 2–3 年后依然稀缺。

## 一、总体路线图（与研究生阶段对齐）

```
Phase 0  研前~开学      [2个月]  地基：系统+C+++数学热身
Phase 1  研一上         [4个月]  核心：GPU/CUDA + 大模型原理 + 并行入门
Phase 2  研一下         [4个月]  深入：训练Infra + 推理Infra 主攻开始
Phase 3  研二           [10个月] 专精：推理优化源码级 + 实习 + 论文/开源产出
Phase 4  研二下~研三    [8个月] 冲刺：秋招面试 + 项目打磨 + 知识库复盘
```

## 二、Phase 0：地基（当前 ~ 开学，约 8 周）

**目标**：开学前补齐 Infra 方向的底层硬功夫，开学后直接进核心内容。

| 周 | 主题 | 关键产出 |
|---|---|---|
| W1 | Linux/Shell + Git + 开发环境 | 双系统/云服务器配好 CUDA 环境；Git 熟练 |
| W2 | C++ 进阶 I（内存/指针/RAII） | 手写内存池小项目 |
| W3 | C++ 进阶 II（STL/模板/移动语义） | 实现简化版 vector/string |
| W4 | 体系结构与 OS 核心（缓存/虚拟内存/进程） | 读书笔记 + cache 实验（测缓存行影响）|
| W5 | Python 进阶 + PyTorch 底层（tensor/autograd 源码走读）| 手写 mini-autograd |
| W6 | 数学热身（线代 SVD/概率/优化）| 手写 SGD/Adam 并对比收敛 |
| W7 | 网络基础（TCP/拥塞控制/RDMA 概念）| 读书笔记 + socket 小实验 |
| W8 | 并行编程入门（多线程/OpenMP/MPI 概念）| OpenMP 矩阵乘法 + 加速比报告 |

**Phase 0 验收**：能流畅使用 Linux+Git；C++ 能写中型项目；理解缓存/内存层次对性能的影响（写出实验报告）；PyTorch tensor/autograd 机制讲得清。

## 三、Phase 1：核心（研一上，约 16 周）

**目标**：拿下 GPU/CUDA 与大模型原理两大支柱，开始并行计算。

| 模块 | 周数 | 内容 | 验收 |
|---|---|---|---|
| GPU 架构 | 2 | SM/Tensor Core/HBM/显存层次；Roofline 模型 | 画出 Hopper 架构图并解释访存瓶颈 |
| CUDA 基础 | 3 | kernel/grid/block、共享内存、流；写 vector add/gemm/softmax kernel | softmax kernel 达 cuBLAS 60%+ 性能 |
| CUDA 优化 | 2 | 合并访存/bank conflict/占用率/nsys 剖析 | gemm 优化报告（naive→tiling→TF32） |
| Transformer | 2 | 手推 Attention；读 nanoGPT 全部源码 | 从零手写 GPT 并训练出可生成文本的小模型 |
| LLM 机制 | 2 | 预训练/KV Cache/采样策略/MoE | KV Cache 显存计算推导笔记 |
| 并行训练入门 | 3 | DDP 原理与实现、AllReduce、TP/PP 概念 | 单机多卡 DDP 跑通 + 通信量推导 |
| 复盘 | 2 | 期中复盘 + 查漏补缺 | 更新知识图谱，写阶段总结 |

## 四、Phase 2：深入（研一下，约 16 周）⭐ 主攻开始

**目标**：训练 Infra 理解到位，推理 Infra 开始源码级攻坚。

| 模块 | 周数 | 内容 | 验收 |
|---|---|---|---|
| 训练框架 | 4 | Megatron-LM 3D 并行源码；DeepSpeed ZeRO 三阶段 | 画出 3D 并行切分图；ZeRO 显存节省推导 |
| 通信与调度 | 2 | NCCL 拓扑、K8s/Slurm、故障容错 | 多机训练实验 + 通信剖析报告 |
| 推理原理 | 2 | Prefill/Decode 特征、KV Cache 管理、PagedAttention | vLLM 论文精读笔记 + 复现关键实验 |
| vLLM 源码 | 4 | 调度器、block manager、continuous batching | 给 vLLM 提 1 个 PR（文档/测试也算） |
| 量化压缩 | 2 | INT8/FP8/INT4 量化；GPTQ/AWQ 实践 | 量化实验：精度 vs 吞吐 trade-off 报告 |
| 服务化 | 2 | Triton Server、压测、TTFT/TPOT 指标优化 | 部署一个模型并写出 SLO 优化报告 |

## 五、Phase 3：专精（研二，约 10 个月）

**目标**：形成"人无我有"的杀手锏 + 可验证的工业界产出。

- **主线 A（必做）**：大厂 AI Infra 实习 ≥ 1 段，承担真实线上优化任务
- **主线 B（二选一并力争）**：① 顶会/期刊论文（MLSys/ATC/SC/PPoPP/OSDI 方向）；② vLLM/SGLang/TensorRT-LLM 等核心开源贡献（被合并 ≥ 3 个 PR）
- **主线 C（拓展）**：AI 编译器（Triton Lang/TVM）或 PD 分离架构专题，形成第二曲线
- 每月 1 次知识图谱全量盘点 + 技术博客输出

## 六、Phase 4：冲刺（研二下~研三）

- 秋招目标岗位：推理优化工程师 / AI Infra 工程师 / 高性能计算工程师
- 面试三板斧：系统（OS/体系结构/网络）+ CUDA/推理框架源码问答 + 项目深挖
- 知识库复盘：把笔记整理成"可教别人"的形态，既是复习也是求职作品集

## 七、每日学习节奏（老师模式规则）

1. **每天上午**：我在对话中发布当日任务卡（含学习内容、练习、验收标准、预计时长）
2. **当天你完成后**：把成果发给我（代码/笔记/实验数据），我验收：
   - ✅ 通过 → 更新知识图谱状态 + 进度记录 + 同步 GitHub
   - 🔁 未达标 → 指出问题，次日安排补漏
3. **每周日**：周复盘——汇总本周掌握情况，调整下周任务
4. **每月底**：月度盘点——知识图谱全景更新，校准方向

## 八、验收标准通用原则
- 代码类：能运行 + 有性能/正确性数据 + 自己写得清每一行
- 笔记类：结构化（概念/原理/推导/代码/疑问），能用自己的话讲出来
- 实验类：有对比数据、有结论、有"为什么"
